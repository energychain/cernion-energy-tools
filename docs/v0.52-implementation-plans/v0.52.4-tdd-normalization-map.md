# v0.52.4 — TDD Matrix Normalization Map

Diese Datei dokumentiert die feste Normalisierungslogik fuer die TDD-Matrix aus
[personal-agent-v052-architecture-tdd.md](personal-agent-v052-architecture-tdd.md).

## Ziel

Die Architektur-Matrix ist absichtlich fachlich formuliert und enthaelt teilweise
konzeptionelle oder alternative Endpoint-Namen (z. B. `... oder ...`).
Fuer automatisierte CI-Tests braucht der Agent jedoch **deterministische**,
**ausfuehrbare** Backend-Aliase.

Deshalb gilt in v0.52.4:

1. Jeder Matrix-Testfall `T-*` wird geparst.
2. Jeder `T-*` wird ueber eine feste Map auf reale API-Aliase normalisiert.
3. Nur **passed** Zaehler sind gueltig fuer Coverage.
4. Coverage muss bei `100%` liegen, sonst Exit Code `1`.

## Wichtige Normalisierungsbeispiele

- `T-EDM-04`
  - Spec: `POST /api/edm-validation/validate`
  - Normalisiert: `POST /edm/validate`

- `T-EDM-06`
  - Spec: `POST /api/edm-virtual/virtual/populate-slp`
  - Normalisiert: `POST /edm/virtual/populate-slp`

- `T-MKT-01`, `T-MKT-02`
  - Spec: ENTSOE / energy-market Punktendpoints
  - Normalisiert: `GET /dashboard/market-snapshot` (aggregierter Markt-Snapshot im aktuellen Backend)

- `T-QUE-04`
  - Spec: `GET /api/observability/summary` + `GET /api/system/status`
  - Normalisiert: `GET /observability/summary` + `GET /dashboard/observability-mini`

## Governance-Regel

Aenderungen an Spec-IDs oder Endpoint-Semantik muessen immer in **beiden** Artefakten
aktualisiert werden:

1. [personal-agent-v052-architecture-tdd.md](personal-agent-v052-architecture-tdd.md)
2. [src/personal-agent-tdd-matrix-normalizer.js](../../src/personal-agent-tdd-matrix-normalizer.js)

Ohne konsistente Aktualisierung schlaegt die CI absichtlich fehl.
