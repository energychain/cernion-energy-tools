# v0.52.9 — Inhouse Data / Multimodal (File Attachments) — Implementierungsplan

> **For Hermes:** Use `subagent-driven-development` skill to implement this plan task-by-task.
> **Scope:** Personal Agent + API Gateway Erweiterung. Keine neuen fachlichen Services — nur Orchestrierung und File-Injektion in L3/L4.

**Goal:** Der Endpunkt `/api/personal-agent/chat` akzeptiert Datei-Anhaenge (Excel, CSV, SAP-Screenshots) via `multipart/form-data`. Diese werden sicher verarbeitet und als multimodaler Kontext in die L3 Session History des Personal Agents injiziert, damit der Agent darueber referenzieren und Schluesse ziehen kann.

**Architecture:** Erweiterung des bestehenden `personal-agent.chat` Endpunkts und der API-Gateway-Routenkonfiguration. Die Aenderungen sind ausschliesslich im API-Gateway (`api.service.js`) fuer den Upload-Handling sowie im `personal-agent` Service fuer die File-Injektion. Die eigentliche Inhaltsanalyse (Tabellenstruktur-Extraktion, OCR) wird als Orchestrierung an existierende Backend-Services delegiert (z.B. `datasource-registry`, `knowledge-rag`, oder ein dediziertes Ingest-Service). Dateien werden temporaer auf dem Filesystem gehalten und mit Tenant-Isolation verwaltet.

**Tech Stack:** Node.js Moleculer, moleculer-web (mit `multipart/form-data` bodyParser), Object-Store, `papaparse` (bereits transitiv vorhanden), `xlsx` (bereits transitiv via `sheetjs`), `llm-client` (fuer OCR-Summary optional).

## 1. Architektur-Blaupause

### 1.1 Designprinzipien (immer diese 6)

| # | Prinzip | Begruendung |
|---|---------|-------------|
| 1 | **Keine fachliche Neuerfindung** | File-Content-Parsing (CSV/Excel) existiert bereits in `datasource-registry` und `energy-sharing-allocation`. Kein neuer Parser. |
| 2 | **Deterministisches Routing vor LLM-Halluzination** | File-Typ und Schema werden deterministisch erkannt (MIME + Magic Bytes), nicht per LLM. |
| 3 | **Kontext-Atmung via Zwiebelmodus** | L3 speichert `fileAttachments` als spezielles History-Element (role: `user`, type: `file_attachment`). L4 kann Tool-Schema fuer einen CSV-Parser oder OCR-Summary-Service dynamisch injizieren. |
| 4 | **Durable Execution** | File-Verarbeitung ist synchron im Request-Pfad (z.B. CSV-Extraktion). Langlaufende OCR/Analyse wird als Durable Task in die Session gekettet (v0.52.2). Already supported. |
| 5 | **Silent-Failure-Verbot** | Wenn File-Parsing fehlschlaegt, muss die Response einen klaren `fileProcessing` Block mit Fehlerdetails tragen. Nie "Datei akzeptiert" bei internem Fehler. |
| 6 | **Asynchrones Träumen** | Post-Session Verlauf wird durch `dream`-Worker aufbereitet. File-Uploads werden als `fileAttachment` Eintraege in L3 gespeichert; bei nächsten Session-Turns sind sie sofort referenzierbar. |

### 1.5 Tool-Orchestrierung & Routing — Unveraendert

```text
Nutzer-Prompt + fileAttachments
    |
    v
capability-broker.recommend (unveraendert — File-Handling beeinflusst Routing NICHT)
    |-- Curated Match (score > 0) -> wie bisher
    |-- No Match -> interface-placeholder.markGap (wie bisher)
```

**Wichtig:** File-Attachments sind REIN KONTEXT (L3), nicht Routing-Eingabe. Der Nutzer kann sagen: "Analysiere diese CSV" und ein Attachment mitliefern — die Routing-Entscheidung basiert immer noch auf dem Text-Prompt, nicht auf dem Datei-Inhalt. Der Inhalt wird im Execution-Schicht (L4) als Input fuer Tools verwendet.

## 3. API-Erweiterung (`api.service.js`)

### 3.1 Route-Konfiguration

Der `personal-agent.chat`-Endpunkt in `api.service.js` (Zeile ~1060) muss `multipart/form-data` akzeptieren:

```javascript
// In services/api.service.js, im routes-Block (settings.routes):
{
  path: '/api/personal-agent/chat',
  mappingPolicy: 'restrict',
  aliases: {
    'POST /chat': 'personal-agent.chat',
  },
  // NEU: multipart/form-data bodyParser fuer diesen Pfad
  bodyParsers: {
    json: false, // standardmaessig fuer diesen Pfad abschalten
    urlencoded: false,
    multipart: {
      enabled: true,
      uploadDir: UPLOAD_DIR, // bereits definiert in api.service.js
      maxFileSize: 10 * 1024 * 1024, // 10 MB
      maxFiles: 5,
      maxFields: 10,
    },
  },
  onBeforeCall(ctx, route, req) {
    // Wenn multipart, konvertiere req.$params zu moleculer-compatiblen ctx.params
    if (req.$multipart) {
      const fields = req.$params || {};
      const files = req.$params?.files || req.$params?.fileAttachments || [];
      ctx.params = {
        ...fields,
        fileAttachments: Array.isArray(files) ? files : [files].filter(Boolean),
      };
    }
  },
}
```

**Hinweis:** Standardmaessig verwendet moleculer-web `busboy` fuer multipart. Die Konfiguration oben verwendet die moleculer-web-eigene Multipart-Unterstuetzung.

### 3.2 Tenant-Isolierter Upload-Pfad

Jeder Upload landet in `uploads/${tenantId}/${sessionId}/fa_${attachmentId}.${ext}`:

```javascript
function buildTenantUploadPath(tenantId, sessionId, attachmentId, ext) {
  const safeTenant = tenantId.replace(/[^a-zA-Z0-9_-]/g, '_');
  const safeSession = sessionId.replace(/[^a-zA-Z0-9_-]/g, '_');
  return path.join(UPLOAD_DIR, safeTenant, safeSession, `fa_${attachmentId}.${ext}`);
}
```

Nach Session-Ende (Garbage Collection im Dreamer, >7 Tage) wird das Upload-Verzeichnis fuer die Session geloescht.

// src/personal-agent-file-handler.js
'use strict';

const fs = require('fs');
const path = require('path');

const FILE_TYPE_MAP = Object.freeze({
  '.csv': { mimeType: 'text/csv', category: 'tabular' },
  '.xlsx': { mimeType: 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet', category: 'tabular' },
  '.xls': { mimeType: 'application/vnd.ms-excel', category: 'tabular' },
  '.png': { mimeType: 'image/png', category: 'image' },
  '.jpg': { mimeType: 'image/jpeg', category: 'image' },
  '.jpeg': { mimeType: 'image/jpeg', category: 'image' },
  '.pdf': { mimeType: 'application/pdf', category: 'document' },
});

const MAX_FILE_SIZE_BYTES = 10 * 1024 * 1024; // 10 MB
const MAX_SAMPLE_ROWS = 5;

function recognizeFileType(filePath) {
  if (!filePath || !fs.existsSync(filePath)) {
    throw new Error('FILE_NOT_FOUND');
  }
  const stat = fs.statSync(filePath);
  if (stat.size > MAX_FILE_SIZE_BYTES) {
    throw Object.assign(new Error('FILE_TOO_LARGE'), { code: 'FILE_TOO_LARGE', maxSize: MAX_FILE_SIZE_BYTES });
  }
  const ext = path.extname(filePath).toLowerCase();
  const meta = FILE_TYPE_MAP[ext];
  if (!meta) {
    throw Object.assign(new Error('INVALID_FILE_TYPE'), { code: 'INVALID_FILE_TYPE', allowed: Object.keys(FILE_TYPE_MAP) });
  }
  // Simple magic-byte verification for CSV
  if (meta.mimeType === 'text/csv') {
    const fd = fs.openSync(filePath, 'r');
    const buf = Buffer.alloc(64);
    fs.readSync(fd, buf, 0, 64, 0);
    fs.closeSync(fd);
    const preview = buf.toString('utf-8');
    if (!preview.includes(',') && !preview.includes(';') && !preview.includes('\t')) {
      throw Object.assign(new Error('INVALID_FILE_TYPE'), { code: 'INVALID_FILE_TYPE', reason: 'File does not look like CSV' });
    }
  }
  return { ...meta, sizeBytes: stat.size, ext };
}

function parseCsvExtract(filePath) {
  const content = fs.readFileSync(filePath, 'utf-8');
  const lines = content.split(/\r?\n/).filter((l) => l.trim() !== '');
  if (lines.length === 0) return { type: 'csv', rowCount: 0, columnCount: 0, headers: [], sampleRows: [], summary: 'Leere CSV-Datei.' };
  const delimiter = lines[0].includes(';') ? ';' : (lines[0].includes('\t') ? '\t' : ',');
  const headers = lines[0].split(delimiter).map((h) => h.trim());
  const dataRows = lines.slice(1);
  const sampleRows = dataRows.slice(0, MAX_SAMPLE_ROWS).map((row) => row.split(delimiter).map((c) => c.trim()));
  return {
    type: 'csv',
    rowCount: dataRows.length,
    columnCount: headers.length,
    headers,
    sampleRows,
    summary: `${dataRows.length} Zeilen, ${headers.length} Spalten (${headers.join(', ')}).`,
  };
}

function parseExcelExtract(filePath) {
  // Delegiere an existierende xlsx-Bibliothek (bereits im Projekt via sheetjs/xlsx)
  // eslint-disable-next-line global-require
  const XLSX = require('xlsx');
  const workbook = XLSX.readFile(filePath, { cellFormula: false, cellNF: false, cellStyles: false });
  const sheets = workbook.SheetNames.map((name) => {
    const sheet = workbook.Sheets[name];
    const range = XLSX.utils.decode_range(sheet['!ref'] || 'A1');
    const rowCount = range.e.r; // 0-indexed, so rowCount = e.r (since header is row 0)
    const json = XLSX.utils.sheet_to_json(sheet, { header: 1, range: 0, limit: MAX_SAMPLE_ROWS + 1 });
    const headers = Array.isArray(json[0]) ? json[0].map(String) : [];
    const sampleRows = json.slice(1, MAX_SAMPLE_ROWS + 1);
    return { name, rowCount, columnCount: headers.length, headers, sampleRows };
  });
  return {
    type: 'excel',
    sheetCount: sheets.length,
    sheets,
    summary: `${sheets.length} Sheet(s): ${sheets.map((s) => `${s.name} (${s.rowCount} Zeilen)`).join(', ')}.`,
  };
}

function ocrExtractImage(filePath) {
  // MVP: Return placeholder — OCR wird via externer Service oder llm-client.summary implementiert
  // In v0.52.9-MVP: Heuristische Dateiname-Analyse + statischer Hinweis
  const fileName = path.basename(filePath);
  return {
    type: 'ocr_summary',
    recognizedText: null,
    summary: `Bild-Datei "${fileName}" hochgeladen. OCR-Textextraktion ist in dieser Version eingeschraenkt — bitte beschreiben Sie den Inhalt kurz im Chat, falls relevant.`,
    language: 'de',
  };
}

function extractDocumentText(filePath) {
  // MVP: PDFs werden nicht geparst (nur als Blob referenziert)
  const fileName = path.basename(filePath);
  return {
    type: 'pdf_text',
    recognizedText: null,
    summary: `PDF-Dokument "${fileName}" hochgeladen. Vollstaendige Textextraktion ist in dieser Version eingeschraenkt.`,
    pageCount: null,
  };
}

function injectFileIntoL3(session, fileMeta) {
  if (!session) session = {};
  if (!session.l3) session.l3 = {};
  if (!Array.isArray(session.l3.fileAttachments)) session.l3.fileAttachments = [];
  session.l3.fileAttachments.push({
    ...fileMeta,
    ts: new Date().toISOString(),
    usedInExecution: false,
    executionReference: null,
  });
  return session;
}

module.exports = {
  recognizeFileType,
  parseCsvExtract,
  parseExcelExtract,
  ocrExtractImage,
  extractDocumentText,
  injectFileIntoL3,
  MAX_FILE_SIZE_BYTES,
  ALLOWED_EXTENSIONS: Object.keys(FILE_TYPE_MAP),
};

async handler(ctx) {
  const tenantId = getTenantId(ctx);
  const userId = String(ctx.meta?.authUser?.userId || 'anonymous');
  const sessionId = String(ctx.params.sessionId || `pa_${crypto.randomUUID()}`);
  const executionMode = normalizeExecutionMode(ctx.params.executionMode);
  const session = await this.loadSession(ctx, tenantId, sessionId, userId, {

  });

  // NEU: File Attachments verarbeiten
  const fileAttachments = ctx.params.fileAttachments || [];
  for (const file of fileAttachments) {
    try {
      const typeInfo = recognizeFileType(file.tempPath);
      let extract;
      switch (typeInfo.category) {
        case 'tabular':
          if (typeInfo.ext === '.csv') extract = parseCsvExtract(file.tempPath);
          else if (typeInfo.ext === '.xlsx' || typeInfo.ext === '.xls') extract = parseExcelExtract(file.tempPath);
          break;
        case 'image':
          extract = ocrExtractImage(file.tempPath);
          break;
        case 'document':
          extract = extractDocumentText(file.tempPath);
          break;
        default:
          extract = { type: 'unknown', summary: `Dateityp ${typeInfo.mimeType} wird in dieser Version nicht unterstuetzt.` };
      }
      injectFileIntoL3(session, {
        attachmentId: file.attachmentId,
        fileName: file.fileName,
        mimeType: file.mimeType,
        category: typeInfo.category,
        sizeBytes: file.sizeBytes,
        extract,
      });
    } catch (fileErr) {
      injectFileIntoL3(session, {
        attachmentId: file.attachmentId,
        fileName: file.fileName,
        mimeType: file.mimeType,
        category: 'unknown',
        sizeBytes: file.sizeBytes,
        extract: null,
        error: { code: fileErr.code || 'FILE_PROCESSING_ERROR', message: fileErr.message },
      });
    }
  }

  // ... restlicher chat handler wie bisher
}

synthesizeTurn({ message, toolContext, executionMode, plan, execution, session }) {
  const attachments = session?.l3?.fileAttachments || [];
  let intro = '';
  if (attachments.length > 0) {
    const okAttachments = attachments.filter((a) => !a.error);
    const failedAttachments = attachments.filter((a) => a.error);
    if (okAttachments.length > 0) {
      intro += `Ich habe ${okAttachments.length} Datei(en) erhalten.`;
      for (const att of okAttachments) {

      }
      intro += ' ';
    }
    if (failedAttachments.length > 0) {
      intro += `Bei ${failedAttachments.length} Datei(en) ist ein Fehler aufgetreten (${failedAttachments.map((a) => a.fileName).join(', ')}). `;
    }
  }
  // ... restliche Synthese wie bisher, aber mit `intro` preprended

## 8. Offene Considerations — Entscheidungen

### C1: Parse-Fehlerstrategie — Teilerfolg mit `fileProcessing`-Fehlern

**Entscheidung:** Harte Ablehnung (HTTP 4xx) NUR fuer Gateway-Level-Fehler (ungueltiger Dateityp, Datei zu gross). Alle Parser-Fehler (corruptes Excel, unlesbare PDF) werden als **Teilerfolg** behandelt: Der Chat-Turn laeuft weiter, das fehlerhafte Attachment wird mit `error` Block in L3 gespeichert, und die Response enthaelt einen `fileProcessing` Array, der pro Datei `ok` oder `error` traegt.

**Begruendung:** Der Nutzer hat moeglicherweise 3 Dateien hochgeladen, davon ist eine corrupt. Es waere unbefriedigend, den gesamten Chat-Turn abzubrechen. Stattdessen sagt der Agent: "Ich habe 2 von 3 Dateien verarbeitet. Bei 'kaputt.xlsx' ist ein Parse-Fehler aufgetreten — bitte pruefen Sie das Format."

**Contract:**

```json
{
  "fileProcessing": [
    { "attachmentId": "fa_01", "fileName": "ok.csv", "status": "ok" },
    { "attachmentId": "fa_02", "fileName": "kaputt.xlsx", "status": "error", "error": { "code": "PARSE_ERROR", "message": "..." } }
  ]
}
```

**TDD-Abdeckung:** T-NEG-File-003 (corruptes Excel als Teilerfolg)

### C2: Limits — 5 Dateien, 10 MB pro Datei, 50 MB Gesamt

**Entscheidung:**

| Limit | Wert | Begruendung |
|-------|------|-------------|
| Max Dateien pro Upload | 5 | UI-Datei-Picker mit Multi-Select; mehr als 5 Dateien verwirren den Kontext |
| Max Dateigroesse pro Datei | 10 MB | CSV/Excel-Dateien in der Energiewirtschaft sind typisch < 5 MB; 10 MB gibt Puffer fuer grosse Excel-Sheets |
| Max Gesamtgroesse pro Request | 50 MB | 5 x 10 MB; verhindert DoS via Multipart-Flood |
| Max Felder (non-file) | 10 | `message`, `sessionId`, `executionMode`, `knownContext`, `toolContext` + Reserve |

**Gateway-Enforcement:**
- `maxFiles` = 5 (busboy/moleculer-web native)
- `maxFileSize` = 10 * 1024 * 1024 (busboy)
- Zusaetzlich: `maxTotalSize` pruefung in `onBeforeCall` — wenn Summe aller Dateien > 50 MB -> HTTP 413

**TDD-Abdeckung:** T-NEG-File-002 (einzelne Datei zu gross), T-NEG-File-004 (Multi-File mit 3 Dateien)

### C3: PDF-Strategie im MVP — Nur Metadaten, keine Textextraktion

**Entscheidung:** PDFs werden im MVP **NICHT aktiv geparst**. Stattdessen wird nur Metadaten/Summary extrahiert (Dateiname, Groesse, MIME-Type) und ein Hinweis an den Nutzer ausgegeben: "Das PDF-Dokument 'XYZ.pdf' wurde hochgeladen. Die automatische Textextraktion ist in dieser Version eingeschraenkt."

**Begruendung:**
1. PDF-Textextraktion ist komplex (verschachtelte Formate, eingebettete Bilder, Scan-PDFs ohne OCR-Layer)
2. Es gibt bereits einen existierenden `znp-pdf-extractor` im Projekt (`src/znp-pdf-extractor.js`), aber der ist spezialisiert auf VNB-Strukturberichte (Layer 2 PDFs), nicht generische Dokumente
3. Wenn Nutzer PDF-Inhalte brauchen, koennen sie diese als Text kopieren und ins Chat-Feld einfuegen — der Workaround ist akzeptabel fuer MVP
4. Spaetere Version (v0.53+) kann PDF-Extraktion via `pdf-parse` oder `mammoth` nachruesten

**L3-Schema fuer PDF im MVP:**

```json
{
  "attachmentId": "fa_pdf01",
  "fileName": "bericht.pdf",
  "mimeType": "application/pdf",
  "category": "document",
  "sizeBytes": 204800,
  "ts": "2026-05-15T14:30:00Z",
  "extract": {
    "type": "pdf_placeholder",
    "summary": "PDF-Dokument 'bericht.pdf' (200 KB). Automatische Textextraktion in dieser Version eingeschraenkt."
  },
  "usedInExecution": false
}
```

**TDD-Abdeckung:** T-FILE-001, T-FILE-002 (CSV/Excel vollstaendig), T-FILE-003 (Bild mit OCR-Summary). Kein dedizierter PDF-Test, da PDF nur als Placeholder behandelt wird.

## 9. Risikoabschaetzung

| Risiko | Frage | Massnahmen |
|--------|-------|------------|
| **Halluzination** | Kann ein Nutzer die Response als fachliche Wahrheit missverstehen? | File-Extract wird immer mit `summary` + `sampleRows` geliefert. Der Agent FORMULIERT nie "laut Datei XY" ohne dass XY tatsaechlich in `l3.fileAttachments` existiert. Die Antwort referenziert immer `attachmentId`. |
| **Fallback-Flood** | Fuehrt File-Upload zu zu vielen unwirksamen Empfehlungen? | Nein — File-Attachments sind reiner Kontext, kein Fallback. Wenn `capability-broker.recommend` keinen Match findet, greift `interface-placeholder.markGap` wie bisher. |
| **Graph-Uebersichtlichkeit** | Wachsen CYA/Prozessgraphen durch neue Knoten unleserlich? | Nein — v0.52.9 fuehrt KEINE neuen CYA/Prozessgraph-Knoten ein. File-Attachments sind L3-Session-Daten, kein Graph-Konzept. |
| **Datenverlust bei Restart** | Ist In-Memory-State im MVP akzeptabel dokumentiert? | Die Upload-Dateien liegen auf dem Filesystem (nicht In-Memory). L3-Persistenz ist in Object-Store / PouchDB. Restart-sicher. Garbage Collection (>7 Tage) ist dokumentiert. |
| **HITL-Flood** | Erzeugt `hard`-Blockade zu viele Mensch-in-der-Schleife Tasks? | Nein — File-Uploads sind nie `hard`-Blockade. Bei Parser-Fehlern wird `fileProcessing.error` in der Response zurueckgegeben (Teilerfolg, kein HITL). |
| **Tenant-Leakage** | Koennte ein Nutzer von Tenant A Dateien von Tenant B sehen? | Upload-Pfad ist `uploads/${tenantId}/${sessionId}/`. Der `personal-agent` Service prueft bei jedem `getSession`, dass die Session zum aufrufenden Tenant gehoert. Cross-Tenant-Zugriff wird durch `getTenantId(ctx)` erzwungen. T-NEG-File-006 testet dies. |
| **DoS via File-Upload** | Koennte ein Nutzer das System via grosse Dateien ueberlasten? | Limits: 5 Dateien, 10 MB pro Datei, 50 MB Gesamt. Gateway blockiert vor dem Service-Call. `api.service.js` `classifyEndpointClass` klassifiziert `POST /api/personal-agent/chat` als `compute` (bereits vorhanden) — Quota/Rate-Limit greifen. |
