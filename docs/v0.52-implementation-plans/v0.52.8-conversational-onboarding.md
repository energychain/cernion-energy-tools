# v0.52.8 — Conversational Onboarding (Missing Context Handling) — Implementierungsplan

> **For Hermes:** Use `subagent-driven-development` skill to implement this plan task-by-task.
> **Scope:** Personal Agent + Async Dream Pipeline Erweiterung. Keine neuen fachlichen Services.

**Goal:** Der Personal Agent erfragt fehlenden Kontext (z.B. VNB-Zugehörigkeit, Rolle, PLZ) dynamisch im Chat, anstatt mit `MISSING_INPUTS` abzubrechen. Der Async Dreamer extrahiert diese Antworten aus L3 und härtet sie ins L2-Profil.

**Architecture:** Erweiterung der bestehenden `personal-agent` Orchestrierung um einen "Missing Context Handler" (MCH). Der MCH wird in `personal-agent-routing.js` als neuer Zwischenlayer eingebaut: nach Plan-Generierung, vor Execution. Wenn `getMissingInputs` > 0 Treffer liefert, schaltet der MCH in den `conversational_onboarding` Modus: Stopp der deterministischen Execution, natürlichsprachliche Rückfrage generieren, Nutzerantwort in Session L3 speichern. Beim nächsten `chat`-Turn erkennt der MCH vorab, ob in L3 unbeantwortete Kontextfragen liegen, und reichert `knownContext` automatisch an. Der Dreamer (`personal-agent-dreamer.js`) bekommt eine neue `extractOnboardingFacts`-Phase, die systematisch L3 auf "Kontextlieferungen" durch den Nutzer scannt und diese als hochvertrauenswürdige L2-Preferences (confidence=1.0) persistiert.

**Tech Stack:** Node.js Moleculer (bestehend), Object-Store (PouchDB), Redis (Session-Hot-Cache optional), `llm-client` (nur für optionalen `explain` Mode).

## 1. Architektur-Blaupause

### 1.1 Designprinzipien (immer diese 6)

| # | Prinzip | Begruendung |
|---|---------|-------------|
| 1 | **Keine fachliche Neuerfindung** | Onboarding ist nur Orchestrierung. VNB-Lookup bleibt in `grid-operations.vnbLookup`, Rollenverwaltung im Auth/Identity-Layer. |
| 2 | **Deterministisches Routing vor LLM-Halluzination** | `capability-broker.recommend` bleibt unveraendert. Missing Context wird aus `ACTION_REQUIREMENTS` und `ACTION_PARAM_ALIASES` abgeleitet — keine LLM-Ruferage. |
| 3 | **Kontext-Atmung via Zwiebelmodus** | L3 speichert `onboardingQuestions` als spezielles History-Element (role: `system`, type: `onboarding_question`). L2 speichert `onboardingFacts` als Sub-Key von `userProfile`. |
| 4 | **Durable Execution** | Dream-Pipeline ist bereits durable (v0.52.3). Keine neuen Wake-Ups noetig. |
| 5 | **Silent-Failure-Verbot** | Wenn Onboarding-Fakt-Extraktion im Dreamer fehlschlaegt, muss der Audit-Trail Eintrag `onboardingExtraction: { ok: false }` enthalten. |
| 6 | **Asynchrones Träumen** | Post-Session Verlauf wird durch `dream`-Worker aufbereitet. Onboarding-Facts werden in dedizierter Pipeline-Phase extrahiert (nicht inline). |

```javascript
// src/personal-agent-onboarding.js
'use strict';

const crypto = require('crypto');

const ONBOARDING_QUESTION_STATUS = Object.freeze({
  PENDING: 'pending',
  ANSWERED: 'answered',
  STALE: 'stale',
});

const ONBOARDING_PARAM_QUESTIONS = Object.freeze({
  gridOperatorId: { label: 'Netzbetreiber-ID', question: 'Welche Netzbetreiber-ID (z.B. BDEW-Code) verwenden Sie?' },
  gridOperatorName: { label: 'Netzbetreiber', question: 'Fuer welchen Netzbetreiber (z.B. Stadtwerke Muenchen) soll ich die Pruefung durchfuehren?' },
  gridOperatorBdew: { label: 'BDEW-Code', question: 'Kennen Sie den BDEW-Code Ihres Netzbetreibers?' },
  projectId: { label: 'Projekt-ID', question: 'Welche Projekt-ID soll ich verwenden?' },
  communityName: { label: 'Gemeinschaft', question: 'Wie heisst Ihre Energiegemeinschaft (Mieterstrom)?' },
  communityId: { label: 'Gemeinschafts-ID', question: 'Welche Gemeinschafts-ID haben Sie?' },
  fnavProfile: { label: 'fNAV-Profil', question: 'Bitte laden Sie das fNAV-Profil hoch oder beschreiben Sie es.' },
  voltageLevel: { label: 'Spannungsebene', question: 'In welcher Spannungsebene (MS / NS / HS) suchen Sie?' },
  dateFrom: { label: 'Startdatum', question: 'Ab welchem Datum soll die Analyse beginnen (YYYY-MM-DD)?' },
  dateTo: { label: 'Enddatum', question: 'Bis zu welchem Datum soll die Analyse gehen (YYYY-MM-DD)?' },
  forecastDays: { label: 'Prognosetage', question: 'Fuer wie viele Tage soll die Prognose berechnet werden?' },
  postleitzahl: { label: 'Postleitzahl', question: 'Welche Postleitzahl betrifft die Anfrage?' },
  postalCode: { label: 'PLZ', question: 'Welche Postleitzahl betrifft die Anfrage?' },
  location: { label: 'Standort', question: 'Welcher Standort (Stadt / PLZ) ist gemeint?' },
  requestedCapacityKW: { label: 'Kapazitaet', question: 'Welche Kapazitaet (in kW) wird beantragt?' },
  role: { label: 'Rolle', question: 'In welcher Rolle agieren Sie (z.B. VNB, UENB, Betreiber)?' },
});

function buildOnboardingQuestion({ paramKey, action, fallbackText }) {
  const meta = ONBOARDING_PARAM_QUESTIONS[paramKey];
  const questionText = fallbackText || meta?.question || `Bitte geben Sie ${paramKey} an.`;
  return {
    questionId: `oq_${crypto.randomUUID().slice(0, 8)}`,
    paramKey,
    action,
    questionText,
    label: meta?.label || paramKey,
    ts: new Date().toISOString(),
    answeredAt: null,
    answer: null,
    status: ONBOARDING_QUESTION_STATUS.PENDING,
  };
}

function captureOnboardingAnswer({ question, message }) {
  if (!question || !message || typeof message !== 'string') return null;
  const text = message.trim();
  if (text.length === 0) return null;
  // Heuristic: if the message is longer than 2 chars and does not look like a command,
  // treat it as an answer to the pending question.
  const looksLikeAnswer = text.length >= 2 && !text.startsWith('/');
  if (!looksLikeAnswer) return null;
  return {
    ...question,
    answeredAt: new Date().toISOString(),
    answer: text,
    status: ONBOARDING_QUESTION_STATUS.ANSWERED,
  };
}

function findPendingOnboardingQuestion(sessionL3 = {}) {
  const questions = Array.isArray(sessionL3?.onboardingQuestions) ? sessionL3.onboardingQuestions : [];
  return questions.find((q) => q.status === ONBOARDING_QUESTION_STATUS.PENDING) || null;
}

function listAnsweredOnboardingFacts(sessionL3 = {}) {
  const questions = Array.isArray(sessionL3?.onboardingQuestions) ? sessionL3.onboardingQuestions : [];
  return questions
    .filter((q) => q.status === ONBOARDING_QUESTION_STATUS.ANSWERED && q.answer != null)
    .map((q) => ({
      paramKey: q.paramKey,
      value: q.answer,
      answeredAt: q.answeredAt,
      source: 'onboarding-chat',
    }));
}

function markStaleQuestions(sessionL3 = {}, maxAgeHours = 24) {
  const questions = Array.isArray(sessionL3?.onboardingQuestions) ? sessionL3.onboardingQuestions : [];
  const now = Date.now();
  const maxMs = maxAgeHours * 60 * 60 * 1000;
  return questions.map((q) => {
    if (q.status !== ONBOARDING_QUESTION_STATUS.PENDING) return q;
    const age = now - Date.parse(q.ts || q.answeredAt || now);
    if (age > maxMs) {
      return { ...q, status: ONBOARDING_QUESTION_STATUS.STALE };
    }
    return q;
  });
}

module.exports = {
  ONBOARDING_QUESTION_STATUS,
  ONBOARDING_PARAM_QUESTIONS,
  buildOnboardingQuestion,
  captureOnboardingAnswer,
  findPendingOnboardingQuestion,
  listAnsweredOnboardingFacts,
  markStaleQuestions,
};
```

      const answeredFacts = listAnsweredOnboardingFacts(session.l3);
      for (const fact of answeredFacts) {

/**
 * Extract onboarding facts from L3 onboardingQuestions.

 */
function extractOnboardingFactsFromSession(session) {
  const questions = session?.l3?.onboardingQuestions || [];
  const facts = [];
  for (const q of questions) {
    if (q.status === 'answered' && q.answer != null && String(q.answer).trim().length > 0) {
      facts.push({
        paramKey: q.paramKey,
        value: String(q.answer).trim(),
        answeredAt: q.answeredAt,
        questionId: q.questionId,
        source: 'onboarding-chat',
      });
    }
  }

}

function convertFactsToPreferences(facts) {
  const now = new Date().toISOString();
  return facts.map((f) => ({
    key: f.paramKey,
    value: f.value,
    confidence: 1.0,
    updatedAt: f.answeredAt || now,
    source: f.source,

}

// In src/personal-agent-dreamer.js, Methode enrichL2Profile:
// Fuege optionalen Parameter `options = {}` hinzu.
// Wenn options.onboardingMode === true, schreibe in onboardingFacts statt preferences.

async function enrichL2Profile(ctx, tenantId, userId, profileNamespace, preferences, options = {}) {
  if (!preferences || preferences.length === 0) {
    return { merged: {}, conflicts: 0, retries: 0 };
  }

  let retries = 0;
  let conflicts = 0;

  for (let attempt = 0; attempt < OCC_MAX_RETRIES; attempt++) {
    let currentDoc;
    try {
      currentDoc = await ctx.call('object-store.get', { namespace: profileNamespace, key: userId }, { meta: ctx.meta });
    } catch (err) {
      if (_isNotFound(err)) {
        currentDoc = null;
      } else {
        throw err;
      }
    }

    const currentPayload = currentDoc?.payload || { userId, preferences: {}, onboardingFacts: {} };
    const snapshotRev = currentDoc?._rev ?? null;

    const targetKey = options.onboardingMode ? 'onboardingFacts' : 'preferences';
    const mergedTarget = { ...(currentPayload[targetKey] || {}) };

    for (const pref of preferences) {
      const existing = mergedTarget[pref.key];
      if (!existing) {
        mergedTarget[pref.key] = { value: pref.value, confidence: pref.confidence, updatedAt: pref.updatedAt };
      } else {
        const existingConf = existing.confidence ?? 0;
        const newConf = pref.confidence ?? 0;
        if (newConf > existingConf) {
          conflicts += 1;
          mergedTarget[pref.key] = { value: pref.value, confidence: pref.confidence, updatedAt: pref.updatedAt };
        } else if (newConf === existingConf && pref.updatedAt > (existing.updatedAt || '')) {
          mergedTarget[pref.key] = { value: pref.value, confidence: pref.confidence, updatedAt: pref.updatedAt };
        }
      }
    }

    const newPayload = {
      ...currentPayload,
      [targetKey]: mergedTarget,
      updatedAt: new Date().toISOString(),
    };

    try {
      await ctx.call(
        'object-store.put',
        { namespace: profileNamespace, key: userId, payload: newPayload, _rev: snapshotRev },
        { meta: ctx.meta }
      );
      return { merged: mergedTarget, conflicts, retries };
    } catch (writeErr) {
      if (_isConflict(writeErr)) {
        retries += 1;
        if (attempt >= OCC_MAX_RETRIES - 1) throw writeErr;
        await _sleep(50 * (attempt + 1));
        continue;
      }
      retries += 1;
      if (attempt >= OCC_MAX_RETRIES - 1) throw writeErr;
      await _sleep(50 * (attempt + 1));
    }
  }

  return { merged: {}, conflicts, retries };
}

## 7. Risikoabschaetzung

| Risiko | P | Impact | Mitigation |
|--------|---|--------|------------|
| Nutzer verwirrt durch serielle Fragen (mehrere fehlende Inputs) | M | M | `generateOnboardingQuestion` fragt seriell, aber mit Fortschrittsindikator ("Schritt 1 von 3"). Max 3 Fragen pro Turn. |
| Antwort-Erkennung zu permissiv (Unsinn wird als Antwort akzeptiert) | M | M | `captureOnboardingAnswer` nutzt heuristische Validierung (Laenge > 2, kein Slash-Command). Bei VNB-Fragen optional `grid-operations.vnbLookup` als Validator. |
| Dream-Pipeline ueberschreibt manuelle Profilaenderungen | L | H | OCC mit `updatedAt` Tie-Break. Onboarding-Facts haben confidence=1.0, aber `updatedAt` gewinnt bei Gleichstand. Audit-Trail protokolliert Konflikte. |
| Stale Questions ueber 24h nicht erkannt | L | M | `markStaleQuestions` wird bei jedem `loadSession` aufgerufen. Stale Questions werden in L3 als `status: stale` markiert und nicht erneut gestellt, sondern neu generiert. |
| HITL-Flood bei Onboarding-Blockaden | L | H | Onboarding ist `soft`-Blockade, nie `hard`. Keine automatische HITL-Eskalation. |
| Performance: Session-L3 waechst durch Onboarding-Eintraege | M | M | `onboardingQuestions` sind maximal so lang wie die Anzahl fehlender Inputs je Plan. Kompression in `compressLayer3History` behandelt sie wie normale History-Eintraege. |

## 8. Offene Entscheidungen

1. **VNB-Validierung bei Antwort:** Soll `captureOnboardingAnswer` bei `gridOperatorName` sofort `grid-operations.vnbLookup` aufrufen, um die Antwort zu validieren? **Vorschlag:** Im MVP nein — Validierung geschieht erst bei der eigentlichen Action. Im Nachfolge-CR (v0.52.9) kann eine "Smart Onboarding" Validierungsschicht eingefuehrt werden.
2. **Rollen-Erfrage:** Soll die Rolle (VNB, Betreiber, etc.) als globales Onboarding-Fact gefuehrt werden oder tenant-spezifisch? **Vorschlag:** Tenant-spezifisch in L2-Profil, da ein Nutzer in verschiedenen Tenants verschiedene Rollen haben kann.
3. **Mehrsprachigkeit:** Onboarding-Fragen sind derzeit auf Deutsch. Soll `ONBOARDING_PARAM_QUESTIONS` mehrsprachig werden? **Vorschlag:** Im MVP Deutsch. Sprach-Detection aus L2-Profil `preferences.language` kann in v0.52.9 genutzt werden.
4. **UI-Hinweise:** Soll die API ein `onboardingHints`-Feld liefern, damit das UI die Frage als spezielles Formular-Element rendern kann? **Vorschlag:** Ja — `onboardingQuestion` im Response enthaelt `paramKey`, `label`, `questionText`. UI kann daraus ein Input-Feld generieren.
