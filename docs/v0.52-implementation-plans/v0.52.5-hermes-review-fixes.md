# Cernion v0.52.5 — Hermes Code Review Fixes

**Meilenstein:** v0.52.5
**Scope:** Architektur- und Stabilitäts-Fixes aus dem lokalen Hermes Code Review der v0.52-Suite.
**Ziel:** Behebung von Multi-Node-, Persistenz- und API-Fehlern im Personal Agent.

## Findings zur sofortigen Behebung durch CoPilot

Der lokale *Hermes Agent* hat das Code-Diff der letzten Releases geprüft und folgende fünf kritische Mängel in deiner v0.52-Implementierung identifiziert. 
**Bitte setze exakt diese 5 Fixes im Rahmen des v0.52.5 Releases um:**

### 1. Stale request context closed over into async Dream timer
**Datei:** `services/personal-agent.service.js` (chat handler / runDream)
**Problem:** Die `chat`-Action schließt den Moleculer Request `ctx` in einer Closure ein und übergibt ihn an `scheduleDream`, welches per `setTimeout` erst nach 5 Minuten triggert. Ein Moleculer `ctx` ist request-scoped. Die Nutzung eines abgelaufenen Contexts in Hintergrundjobs beschädigt das Distributed Tracing, die Metriken und führt zu Timeout/Auth-Risiken.
**Fix:** Der Dream-Prozess muss Aufrufe über den globalen Broker (oder einen frisch erzeugten internen Context) machen, nicht über den originalen Request-Context.

### 2. Process-local Dream timer registry breaks multi-instance deployments
**Datei:** `src/personal-agent-dreamer.js` (scheduleDream / cancelDream / _dreamTimers)
**Problem:** `_dreamTimers` ist eine prozesslokale `Map`. In einem skalierten Moleculer-Setup (Load Balancer) landet ein zweiter Chat-Request ggf. auf Instanz B. Instanz B kann den Timer auf Instanz A nicht canceln. Der verwaiste Timer auf A löst aus, was zu duplizierten Dream-Runs führt, die dann miteinander auf demselben L2-Profil kollidieren.
**Fix:** Ersetze die lokale `Map` durch einen Distributed Scheduler, eine Distributed Lock Mechanik oder das gerade erst etablierte *Durable Execution Watchdog* Pattern aus v0.52.2.

### 3. Optimistic concurrency guard bypassed on first write attempt
**Datei:** `src/personal-agent-dreamer.js` (enrichL2Profile)
**Problem:** Der Recheck (`recheckUpdatedAt !== snapshotUpdatedAt`) ist hinter `if (attempt > 0)` verborgen. Beim ersten Schreibversuch wird gelesen, das Profil gemerged und geschrieben, ohne zu verifizieren, ob der Datensatz sich dazwischen geändert hat (Time-of-check to time-of-use Bug). Ein paralleler Write wird hier lautlos überschrieben.
**Fix:** Nutze die nativen CAS (Compare-And-Swap) / Revisions-Mechaniken (`_rev`) des zugrundeliegenden Object-Stores bei **jedem** Schreibversuch, nicht nur beim Retry.

### 4. Intra-batch cosine deduplication missing in L1 tenant memory
**Datei:** `src/personal-agent-dreamer.js` (enrichL1TenantMemory)
**Problem:** Nachdem ein neues Faktum persistiert wurde, pusht der Code den Text in `existingTexts`, aber der Einbettungsvektor (`newVec`) wird niemals an `existingVectors` gehängt. Weitere neue Fakten im exakt gleichen Dream-Batch werden also nur gegen Altbestände der DB verglichen, nicht gegen die Fakten, die 10 Millisekunden zuvor in derselben Schleife erzeugt wurden.
**Fix:** Der Vektor (`newVec`) muss innerhalb der Iteration nach dem erfolgreichen Speichern aktiv an das `existingVectors` Array angehängt werden.

### 5. getSession und resetSession fabricate missing sessions instead of 404
**Datei:** `services/personal-agent.service.js` (loadSession)
**Problem:** Wenn `object-store.get` ein 404 zurückgibt, erzeugt `loadSession` von sich aus ein leeres Session-Objekt. `getSession` liefert dies mit HTTP 200 OK zurück. Clients, die eine abgelaufene oder verschriebene `sessionId` anfragen, bekommen eine Blanko-Session statt eines sauberen 404-Fehlers.
**Fix:** Führe ein Flag wie `createIfMissing` in `loadSession` ein. Aktiviere dies **ausschließlich** für die `chat` Action. Schreibgeschützte Endpunkte wie `getSession` oder der `resetSession` Flow müssen bei Nicht-Existenz sauber den `OBJECT_NOT_FOUND` Fehler durchreichen.

## Abschluss
Erstelle für diese Fixes das Release **v0.52.5** und sorge dafür, dass alle bestehenden Matrix-Tests grün bleiben.
