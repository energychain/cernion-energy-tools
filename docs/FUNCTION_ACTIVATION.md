# Function activation (#696)

`services/function-activation.service.js` exposes the read-only Moleculer actions
`activation.list`, `activation.get` and `activation.explain` (service name `activation`).
There are no REST aliases. The service has no LLM, provider, workflow, operation,
agent-creation or authorization calls. Coverage never grants permission.

The implementation follows the original issue and the #693 clarification, as
explicitly requested by the current assignment. The later Phase-B comment in #696
proposing a pure advisory evaluator is not the scope of this implementation.

## State and evidence

Every current function has an Activation with the exact required #693 fields:
`tenantId`, `functionId`, `state`, `touchedAt`, `touchedBy`, `responsibility` and
`reason`. A fresh tenant reads only `latent` states, with empty humans and no CET
responsibility; reading does not create a database document.

- `function.touched.v1` activates the touched function. Tenant, actor, conversation,
  confidence and timestamp are validated. Future and invalid timestamps are rejected.
- Direct neighbors with `weight >= minWeight` and no actor score at or above
  `coverageThreshold` may receive CET responsibility. Missing coverage means no
  qualifying evidence was received, not an authorization conclusion. No recursive
  propagation occurs. Another explicit touch, including work generated by a future
  agent, supplies the next step.
- Direct touches activate independently of budget. A touched function may also be a
  qualifying neighbor of another touched function; such CET responsibility counts
  against the budget. A touch alone does not assert human coverage.
- Candidates are ranked by strongest incoming eligible edge, then canonical UTF-16
  function ID. Exactly `tenantBudget` candidates at most are selected. Optional
  `tenantBudgets` overrides are keyed by tenant. Deferred candidates carry a reason.
- `function.coverage.changed.v1` supplies `{tenantId, actorId, functionId, score,
  origin}`. This service stores that evidence and never calculates scores from turns.
  Equality with `coverageThreshold` qualifies. Multiple actors are considered;
  lowering one score does not remove another actor's coverage.
- High human coverage removes CET responsibility. The durable `reason[]` and private
  transition history record the handoff actor and prior edge evidence. The subsequent
  `function.activation.changed.v1` event requests downstream agent consumers to
  relinquish work; no agent is stopped directly and no agent is created here.

## Time and budget

`restWindowMs` is inclusive: at exactly `touchedAt + restWindowMs` an uncovered
function remains `active`. After it, `dormant` is allowed. An observed `active`
`shared-agent.lifecycle.v1` transition renews recent activity without activating
another hop. Duplicate lifecycle states do not manufacture new activity. A future
agent can issue another explicit touch when doing further work.

Inactive CET candidates relinquish their budget allocation. Reads project current
state without writing. The internal sweep persists time transitions and publishes
notifications; it runs at startup and every `sweepIntervalMs`. Its interval can be
zero in deterministic tests. Published transitions may therefore lag the exact rest
boundary by up to a sweep interval; read results use the current clock immediately.

For each tenant:

- CET-responsible functions <= its budget;
- each is an eligible direct neighbor of a touched function;
- active functions <= unique touched functions + its budget.

All parameters are service settings, injected as data:

| Setting | Default | Meaning |
| --- | ---: | --- |
| `tenantBudget` | 8 | Maximum CET-responsible functions |
| `tenantBudgets` | `{}` | Per-tenant budget overrides |
| `minWeight` | 0.2 | Inclusive edge threshold |
| `coverageThreshold` | 0.5 | Inclusive human evidence threshold |
| `restWindowMs` | 86400000 | Inactivity window in milliseconds |
| `sweepIntervalMs` | 60000 | Internal sweep interval; 0 disables timer |
| `model` | committed model | Injected Function model for tests |
| `clock` | `Date.now` | Test clock injection |

## Persistence, ordering and lineage

PouchDB is opened and closed only by `createPouchDbLifecycleMixin`. The path defaults
 to `./data/function-activation`, overridden by `FUNCTION_ACTIVATION_DB_PATH`.
One document per validated tenant contains touches, received coverage, observed
activity, projected activations, private history and a notification outbox.
Writes serialize per tenant in the repository's single-process broker architecture.
No cross-process consensus is introduced; sharing this database between concurrent
independent writers is not supported by this slice.

Touches use an actor/conversation timestamp watermark; duplicate or older events
for that key are no-ops. Identical coverage states are no-ops, including after a
restart. Coverage events have no event ID or timestamp in #693, so their arrival
order is authoritative. A replayed older *different* coverage value cannot be
identified as stale from that contract alone.

State is committed before notification. The durable outbox is retried on the next
mutation or sweep/startup. Delivery is at least once and coalesces retries to current
state, never stale CET responsibility. Consumers must be idempotent. Published
`function.activation.changed.v1` contains exactly `{tenantId, functionId, state,
responsibility}`. Private history is activation audit data, not #698's Journal service.

Stored IDs are resolved through `resolveFunctionId()` when read. Private source-hash
and capability-membership metadata distinguish the saved scope from an older split
of an ID that was retained by one child. Merges combine touches. Splits map touches
only to surviving intersecting memberships. Human coverage is retained only when
its saved scope resolves unambiguously; an ambiguous incoming coverage or lifecycle
reference is rejected. No coverage or responsibility is blindly copied across a split.
Unknown/fully retired IDs do not produce activations. `get` and `explain` return
`resolutions[]` plus matching `activations[]`, covering multi-successor stored IDs.
`explain` also returns private `history[]` for those identities.

## Real adapter and acceptance

`tests/helpers/shared-service/real-adapter.js` starts this actual service in a real
Moleculer broker. Only the PouchDB constructor used by the existing mixin is replaced
with a revision-checking in-memory test double. Another test uses real PouchDB and
restarts the broker to verify persistence and close behavior. The adapter reports
actual activations, configured graph, budget, clock and rest window. Missing-service
observations (`agents`, `journal`, corrections, and others) stay empty.

Touches and received coverage/lifecycle events are delivered to the real handlers.
Advance steps sweep the service against the test clock. Signals, activity queries
and correction steps belong to other issues and do not mutate this service.
