## Goal

Plan v0.54.2: integrate runtime receipt selection into the Personal Agent while preserving conservative fallback to existing hard-coded logic.

## Required Plan Output

Provide:

- where receipt selection should be called in `services/personal-agent.service.js`
- request parameter contract
- metadata/debug output contract
- fallback behavior
- how receipt-selected plans interact with current consultation execution
- tests to add
- regression protections for existing Personal Agent behavior

## Request Parameters

Plan support for:

- `forceReceipt`
- `preferredReceipts`
- `allowDraftReceipts`
- `explainReceiptSelection`
- `disableReceiptSelection`

Use the project naming style if equivalent names already exist.

## Scope

Include:

- receipt selection call in the Personal Agent flow
- forced receipt handling
- draft receipt permission handling
- diagnostic output when requested
- fallback to current routing if no receipt matches
- no behavioral change when receipt selection is disabled or no receipt is available

Exclude:

- VNB migration as a production receipt
- Knowledge-aware receipt evidence integration
- autonomous learning loop

## Acceptance Criteria

- Existing Personal Agent tests still pass.
- `forceReceipt` selects a valid receipt and fails clearly for invalid ids.
- Draft receipts are ignored unless `allowDraftReceipts` is true.
- No matching receipt falls back to current behavior.
- Receipt selection diagnostics are available when requested.
