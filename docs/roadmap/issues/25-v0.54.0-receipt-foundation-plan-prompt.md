# CoPilot Plan Prompt - v0.54.0 Receipt Foundation

Use `docs/roadmap/issues/25-runtime-receipts-v054-big-picture.md` as mandatory context before planning.

You are in Plan Mode. Do not implement code yet.

## Goal

Plan v0.54.0: introduce the foundation for runtime-managed agent receipts.

The result should be a PouchDB/Datapoints-backed `agent-receipts` service with a validated receipt schema, CRUD actions, and REST endpoints. This milestone should not deeply integrate receipts into the Personal Agent execution path yet.

## Current Known Context

The existing Cookbook service is static and code-managed:

- `services/cookbook.service.js`
- `src/cookbook-recipes.js`

The Personal Agent currently contains hard-coded routing and guardrail logic:

- `services/personal-agent.service.js`
- `src/personal-agent-routing.js`
- `src/consultation-execution-bridge.js`
- `src/consultation-tool-resolver.js`
- `src/personal-agent-knowledge-rag.js`

Find and inspect the existing persistence abstractions before proposing implementation. Prefer existing PouchDB/Datapoints patterns.

## Scope

Include:

- `agent-receipts` service
- receipt schema helper module
- CRUD actions
- list/get/create/update/archive or delete
- status values: draft, active, deprecated, archived
- REST API mapping
- service-level tests

Exclude:

- Personal Agent runtime selection
- VNB receipt migration
- chat-based draft generation
- autonomous learning loop

## Acceptance Criteria

- Receipts can be created, listed, fetched, updated, and archived/deleted through Moleculer actions.
- REST endpoints expose the same foundation behavior.
- Invalid receipts are rejected with clear errors.
- Existing Cookbook behavior is not broken.
- Existing Personal Agent behavior is not changed in this milestone.
- Tests cover happy path and validation failures.
