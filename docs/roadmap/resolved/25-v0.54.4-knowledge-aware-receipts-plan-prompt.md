# CoPilot Plan Prompt - v0.54.4 Knowledge-Aware Receipts

Use `docs/roadmap/issues/25-runtime-receipts-v054-big-picture.md` as mandatory context before planning.

You are in Plan Mode. Do not implement code yet.

## Goal

Plan v0.54.4: let receipts use Knowledge Service evidence, not only coarse Personal Agent hints.

Receipts should be able to define knowledge queries and carry relevant knowledge hit ids/metadata into execution and response policy.

## Current Known Context

`src/personal-agent-knowledge-rag.js` currently reduces knowledge context to domain/regulatory/style hints. This milestone should plan a safe expansion where receipts can request and use specific knowledge evidence without leaking unrelated data or overloading prompts.

## Required Plan Output

Provide:

- receipt schema extensions for knowledge queries/evidence requirements
- integration point with existing Knowledge Service / knowledge-rag
- evidence payload shape
- privacy/scope constraints
- response policy use
- tests to add
- fallback behavior if Knowledge Service is unavailable

## Scope

Include:

- optional `knowledgeQueries` or equivalent receipt field
- ability to include knowledge hit ids and concise summaries in receipt evaluation
- evidence status integration
- safe timeout/degraded behavior

Exclude:

- rewriting the Knowledge Service
- dumping raw long documents into Personal Agent prompts
- autonomous creation of new Knowledge documents
- replacing all existing knowledge-rag behavior

## Acceptance Criteria

- A receipt can request relevant knowledge context.
- Knowledge evidence is traceable by id/metadata.
- Missing or timed-out knowledge lookup degrades safely.
- Personal Agent can use knowledge evidence in response policy without overclaiming.
- Tests cover available, missing, and timeout/degraded knowledge cases.
