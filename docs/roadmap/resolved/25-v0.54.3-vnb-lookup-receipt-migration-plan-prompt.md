## Reference Behavior

The VNB receipt should encode:

1. Detect VNB/BDEW/responsible grid operator intent.
2. Extract available city/operator/BDEW context.
3. Call `grid-operations.vnbLookup` when enough direct input exists.
4. Call `grid-operations.marketPartners` to resolve ambiguous input.
5. Require tool evidence before claiming a verified VNB.
6. Ask for or report missing verification when evidence is insufficient.

## Scope

Include:

- one VNB receipt as active or seeded test fixture
- tests comparing receipt path and current legacy behavior
- `forceReceipt` test path
- fallback path when receipt fails or lacks input

Exclude:

- removing legacy VNB code
- broad migration of all Cookbook recipes
- Knowledge Service deep evidence integration beyond what is already available

## Acceptance Criteria

- VNB lookup can run through a runtime receipt.
- Known VNB cases pass through receipt-selected execution.
- Missing or ambiguous input returns a safe answer.
- Legacy fallback remains available.
- Tests prove no regression in existing Personal Agent VNB behavior.
